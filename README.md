# Domivra

แพลตฟอร์มสำหรับเจ้าของหอพักและคอนโด มี 3 บทบาท: แอดมิน Domivra ดูแลบัญชีลูกค้า, เจ้าของ/ผู้จัดการหอพักดูแลข้อมูลและลูกบ้านของตนเอง, และผู้พักใช้เว็บแอปบนมือถือ

## เริ่มใช้งาน

ต้องมี Node.js 22 ขึ้นไปและ Docker Desktop ที่เปิดอยู่

```bash
cd domivra
npm ci
npm run setup
docker compose up --build -d
```

เปิด [Domivra](http://127.0.0.1:5173/login) ข้อมูลเข้าระบบครั้งแรกของผู้ดูแลแพลตฟอร์มอยู่ใน container:

```bash
docker compose exec -T api cat /app/runtime/platform-credentials.txt
```

ใช้รหัสองค์กร `platform` สำหรับแอดมิน Domivra จากหน้าแพลตฟอร์มสร้างลูกค้า เพิ่มบัญชีเจ้าของ ออกรหัสผ่านใหม่ และพัก/เปิดใช้งานองค์กรได้ เจ้าของหอพักใช้รหัสองค์กรที่ Domivra สร้างให้ แล้วเข้า `/owner` เพื่อดูแลลูกบ้านของตนเอง ส่วน `/app` เป็นเว็บแอปของผู้พัก แต่ละองค์กรมีข้อมูลแยกด้วย `org_id` และ API ตรวจสิทธิ์ตามบทบาททุกคำขอ

การติดตั้งบนเครื่องผู้พัฒนาเดิมย้ายข้อมูลตัวอย่างเข้าองค์กรชื่อ `domivra` แล้ว องค์กรนี้เป็นลูกค้าตัวอย่าง ไม่ใช่บัญชีแอดมินแพลตฟอร์ม บัญชี `admin` และ `resident` ขององค์กรตัวอย่างใช้รหัสเดิมที่เก็บใน `data/initial-credentials.txt` ส่วนการ clone ใหม่จะเริ่มด้วยฐานข้อมูลว่างและบัญชีแพลตฟอร์มหนึ่งบัญชี ห้ามส่งไฟล์รหัสผ่านหรือ `.env` ให้ผู้อื่น

## สแตกที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| เว็บ | Vue 3 Composition API, TypeScript strict, Vite, Tailwind CSS, shadcn-vue, Pinia, Vue Router, TanStack Query for Vue, Axios, VeeValidate + Zod, Lucide |

| พัฒนา/CI | Docker Compose, Vitest, Testcontainers, Playwright, GitHub Actions |


## การใช้งานหลัก

- **แพลตฟอร์ม:** สร้างองค์กรลูกค้าและพัก/เปิดการใช้งาน
- **ผู้ดูแลลูกค้า:** โครงการ ห้อง ผู้พัก สัญญา บิล ตรวจหลักฐานชำระ แจ้งซ่อม รายงานปัญหาส่วนกลาง ประกาศ กฎ ย้ายออก รายงาน และตั้งค่าเบอร์นิติบุคคล/รปภ./ฉุกเฉิน
- **ผู้พัก:** ดูบิล ส่งหลักฐาน แจ้งซ่อม แจ้งพื้นที่ส่วนกลางชำรุดแบบอัปเดตทันที ติดต่อฉุกเฉิน อ่านประกาศ/กฎ ดูสัญญา ลงนามอิเล็กทรอนิกส์ และขอย้ายออก
- **สัญญา:** เอกสารตัวจริงใช้ PDF สแกนและการยืนยันรับฉบับจริง; แบบอิเล็กทรอนิกส์ยืนยันชื่อ รหัสผ่าน และความยินยอม พร้อมเวลาและ SHA-256 ของ PDF ที่ลงนาม
- **นำเข้าห้อง:** `.csv` หรือ `.xlsx` แผ่นแรกไม่เกิน 4 MB / 5,000 แถว หัวตารางต้องมี `property,building,number,floor,rent,deposit,area` และเพิ่ม `room_type,water_meter,electric_meter,owner_name,owner_phone` ได้ ข้อมูลห้องซ้ำถูกข้าม ไฟล์นี้เป็นทะเบียนห้อง ไม่ใช่การนำเข้าข้อมูลระบุตัวตนผู้พัก
- **ข้อมูลของหอพัก:** เมนู “ข้อมูลของหอพัก” นำเข้า CSV หรือ Excel โดยใช้หัวตารางของลูกค้าเอง (หลายแผ่นงานได้) และแสดงตารางตามคอลัมน์ที่นำเข้า จำกัด 4 MB, 20 แผ่นงาน, 200 คอลัมน์ และ 5,000 แถวต่อไฟล์ แถวข้อมูลเข้ารหัสและแยกตามองค์กร เจ้าของลบชุดข้อมูลได้ ข้อมูลนี้ยังไม่สร้างห้อง บิล สัญญา หรือบัญชีผู้พักในโมดูลหลักโดยอัตโนมัติ; หากต้องการใช้งานในโมดูลหลักต้องตรวจการจับคู่คอลัมน์ก่อน
- **ทะเบียนผู้พัก:** เจ้าของหอพักจัดการสัญชาติ ช่องทางติดต่อ ผู้ติดต่อฉุกเฉิน ผู้ร่วมพัก สัตว์เลี้ยง รถ บัตรผ่าน ผู้ได้รับอนุญาต และวันย้ายเข้า/ออกจากเมนูผู้พัก บันทึกผลตรวจห้อง ผู้มาติดต่อ และคำร้องเรียนได้ ข้อมูลสัญญาเช่า/ประวัติแจ้งซ่อมเชื่อมจากรายการเดิม
- **ข้อมูลส่วนตัว:** ตั้งวัตถุประสงค์และจำนวนวันเก็บข้อมูลแยกตามองค์กรในเมนูตั้งค่า ผู้พักยืนยันในหน้า “บัญชีของฉัน” ก่อนบันทึกทะเบียน เลขบัตร/พาสปอร์ตและเลขวีซ่าเข้ารหัสใน PostgreSQL; สำเนาเอกสารเก็บใน S3 ส่วนตัว เจ้าของหอพักเห็นเลขแบบปิดบางส่วนและต้องกดดูเลขเต็มโดยมีบันทึกการเข้าถึง
- **อายุข้อมูล:** ระยะเก็บที่ตั้งไว้ใช้กับทะเบียนและเอกสารส่วนตัวหลังปิดงานย้ายออก ชุดข้อมูลที่นำเข้าแบบอิสระไม่มีตัวบ่งชี้ผู้พัก/วันย้ายออก จึงต้องลบชุดข้อมูลเองเมื่อหมดความจำเป็น

การตรวจรับชำระเป็นการบันทึกผลที่ผู้ดูแลตรวจจากบัญชีธนาคารจริง ระบบไม่โอนเงินเอง การลงนามอิเล็กทรอนิกส์นี้บันทึกหลักฐานการยืนยันในระบบ แต่ยังไม่ใช่ลายมือชื่อดิจิทัลจากผู้ให้บริการรับรอง

## คำสั่งที่ใช้บ่อย

```bash
npm run build
npm test
npm run test:integration
npm run test:e2e
docker compose ps
docker compose logs -f api
docker compose down
```

`test:integration` ใช้ Testcontainers จึงต้องเปิด Docker ส่วน `test:e2e` ต้องมี browser ของ Playwright (`npx playwright install chromium`) GitHub Actions ติดตั้ง browser และรันทุกชุดอัตโนมัติ

## การตั้งค่าและข้อมูลเดิม

`npm run setup` สร้างรหัสสุ่มใน `.env` และไฟล์ `runtime/s3.json` แบบไม่แสดงค่าบนหน้าจอ ก่อนอัปเดต container เดิมให้เรียกคำสั่งนี้อีกครั้งเพื่อเพิ่ม `PII_ENCRYPTION_KEY` โดยไม่เปลี่ยนรหัสที่มีอยู่ สำรองทั้ง `S3_SSE_KEK`, `PII_ENCRYPTION_KEY` และ volume `storage_data`; หากกุญแจหาย จะอ่านเอกสารหรือเลขเอกสารที่เข้ารหัสไว้ไม่ได้ ห้ามเรียก `docker compose down -v` เมื่อยังต้องใช้ข้อมูล

ข้อมูล SQLite เดิมยังอยู่ใน `data/` และไม่ได้ลบ สคริปต์ `npm run migrate:legacy` นำเข้าข้อมูลหลักจากฐานเดิมได้ครั้งเดียว แต่ไม่ย้ายไฟล์หลักฐาน/สัญญาจากระบบเดิม; ในข้อมูลตัวอย่างนี้มีหลักฐานชำระ 1 รายการที่ไม่มีไฟล์ต้นฉบับ จึงไม่ได้นำรายการนั้นเข้าฐานใหม่ ควรเก็บ `data/` เป็นสำเนาอ้างอิง

สำหรับใช้งานนอกเครื่องพัฒนา ให้เตรียม HTTPS, การสำรอง PostgreSQL และ S3, การจัดการกุญแจ และนโยบายยืนยันตัวตน/การลงนามที่เหมาะกับการใช้งานจริง

โค้ดเก่า `server.js` และ `public/` ยังคงอยู่เพื่ออ้างอิง ขณะนี้ `docker compose` เปิดเฉพาะเว็บ Vue และ API PostgreSQL
